# Лексика Z

## 1. Общая модель

Исходный код Z состоит из последовательности символов UTF-8.

Лексический анализ преобразует исходный текст в последовательность токенов.

Лексика Z намеренно минимальна. Правила должны быть однозначными и не требовать
угадывания намерений программиста или контекста программы.

Основные категории токенов:

- идентификаторы;
- ключевые слова;
- числовые литералы;
- строковые литералы;
- операторы;
- разделители;
- комментарии.

Пробелы и комментарии не являются частью синтаксического дерева.

## 2. Кодировка

Исходные файлы Z используют UTF-8.

Имена идентификаторов на первом этапе ограничиваются ASCII-символами. Unicode
разрешён внутри строк и комментариев.

Это уменьшает неоднозначность, упрощает компилятор и делает имена предсказуемыми
для инструментов и моделей ИИ.

## 3. Пробелы и переводы строк

Пробел, табуляция и перевод строки разделяют токены и не изменяют их значение,
кроме правил окончания инструкции.

Несколько пробелов эквивалентны одному пробелу.

Отступы не имеют синтаксического значения.

Следующий код эквивалентен:

```text
x: int = 10
y: int = 20
```

и:

```text
x:int=10

y:int=20
```

## 4. Окончание инструкции

Z не требует `;` в конце каждой инструкции.

Перевод строки может завершать инструкцию, если предыдущий токен может завершать
выражение.

К таким токенам относятся:

- идентификатор;
- числовой литерал;
- строковый литерал;
- `true`;
- `false`;
- `)`;
- `]`;
- `}`;
- `++`;
- `--`.

Перевод строки не завершает инструкцию после операторов, запятых и других токенов,
которые явно продолжают выражение.

Пример:

```z
x := 10
y := 20
```

эквивалентен последовательности двух инструкций.

Перенос выражения допускается:

```z
x := a +
    b
```

## 5. Идентификаторы

Идентификатор состоит из букв ASCII, цифр и `_`.

Первый символ не может быть цифрой.

Примеры:

```text
x
name
user_name
value2
```

Идентификаторы чувствительны к регистру:

```text
name
Name
NAME
```

это три разных идентификатора.

Идентификатор `_` является специальным пустым именем и может использоваться
там, где значение намеренно игнорируется.

## 6. Ключевые слова

Ключевые слова имеют специальное значение и не могут использоваться как обычные
идентификаторы.

Базовый набор Z:

```text
fn
struct
if
else
for
return
import
true
false
```

Ключевые слова добавляются только при необходимости. Язык не должен содержать
несколько ключевых слов для одной концепции.

## 7. Числовые литералы

### 7.1. Целые числа

Целый литерал состоит из одной или более десятичных цифр.

```z
0
1
10
1000
```

Начальные нули не имеют специального значения.

```z
0010
```

означает десятичное число 10.

### 7.2. Числа с плавающей точкой

Число с плавающей точкой содержит десятичную часть.

```z
0.5
10.0
3.1415
```

Экспоненциальная запись на первом этапе не используется.

Шестнадцатеричные, двоичные и восьмеричные литералы также не входят в базовую
лексику Z. Они могут быть добавлены позднее как расширение без изменения
основной модели языка.

## 8. Строковые литералы

Строка заключена в двойные кавычки:

```z
"hello"
"Hello, world!"
```

В строке поддерживаются escape-последовательности:

```text
\\
\"
\n
\t
\r
\0
```

Другие escape-последовательности не являются допустимыми.

Перенос строки внутри обычного строкового литерала запрещён.

Многострочные строки в базовой версии языка отсутствуют. Это уменьшает число
правил и специальных случаев в лексере.

## 9. Комментарии

Z использует однострочные комментарии:

```z
// comment
x := 10 // comment
```

Комментарий начинается с `//` и продолжается до конца строки.

Блочные комментарии `/* ... */` в базовой версии не используются.

Однострочные комментарии проще обрабатывать, проще восстанавливать после ошибок
и они лучше подходят для автоматически генерируемого кода.

## 10. Операторы

Базовый набор операторов:

```text
+
-
*
/
%
==
!=
<
<=
>
>=
&&
||
!
=
:=
+=
-=
*=
/=
%=
++
--
```

Операторы состоят из ASCII-символов.

При наличии нескольких возможных токенов используется наиболее длинный токен.

Например:

```text
==
```

распознаётся как один оператор, а не как два `=`.

Оператор `:=` используется для объявления переменной с выводом типа:

```z
x := 10
```

Оператор `=` используется для присваивания уже объявленной переменной:

```z
x = 20
```

Объявление с явным типом использует `:` и `=`:

```z
x: int = 10
```

## 11. Разделители

Базовые разделители:

```text
(
)
{
}
[
]
,
:
.
```

Каждый разделитель имеет только одно синтаксическое значение.

## 12. Строковое представление токенов

Лексер должен сохранять исходное положение каждого токена в файле.

Для каждого токена рекомендуется хранить:

- тип токена;
- исходный текст;
- номер строки;
- позицию в строке.

Это позволяет компилятору выдавать точные ошибки и возвращать модели ИИ
структурированную информацию о месте ошибки.

## 13. Ошибки лексического анализа

Лексер должен завершать анализ с ошибкой при обнаружении неизвестной или
недопустимой последовательности символов.

Ошибка должна содержать как минимум:

- код ошибки;
- строку;
- позицию;
- короткое описание;
- проблемный фрагмент исходного кода.

Пример:

```text
E001: invalid token at 12:5: '@'
```

Коды ошибок должны быть стабильными. Текст сообщения может изменяться, но код
ошибки должен оставаться совместимым.

## 14. Принципы лексики Z

Лексика Z следует нескольким правилам:

1. Один символ или последовательность символов имеют одно значение.
2. Контекст не должен менять значение токена без необходимости.
3. Синтаксис ASCII-операторов используется вместо альтернативных словесных
   операторов.
4. Новые формы добавляются только при наличии практической необходимости.
5. Лексер должен быть простым, детерминированным и устойчивым к ошибкам ИИ.
6. Правила должны быть удобны как для человека, так и для автоматической
   генерации и анализа кода.
