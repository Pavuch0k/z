# Выражения Z

## 1. Назначение

Выражение Z — конструкция, вычисляющая значение.

Каждое выражение имеет:

- синтаксис;
- тип результата;
- определённый порядок вычисления;
- определённые правила ошибок.

Выражения не изменяют состояние программы, если это явно не предусмотрено их операцией или вызовом функции.

Пример:

x + 10

Здесь `x + 10` — выражение, результатом которого является значение типа `int`.

Выражения могут использоваться:

- в объявлениях;
- в присваиваниях;
- в условиях;
- как аргументы функций;
- как элементы коллекций;
- внутри других выражений;
- как возвращаемое значение функции.


## 2. Общая грамматика

Выражение имеет следующую структуру:

expression :=
    literal
  | identifier
  | unary_expression
  | binary_expression
  | call_expression
  | index_expression
  | field_expression
  | grouped_expression
  | array_literal
  | map_literal
  | struct_literal

При разборе выражений компилятор обязан использовать правила приоритета и ассоциативности, определённые в этой спецификации.

Синтаксически корректное выражение не обязательно является семантически корректным.

Например:

"hello" + 10

может быть разобрано как выражение, но должно быть отклонено проверкой типов.


## 3. Литералы

Z поддерживает следующие базовые литералы:

### 3.1. Целые числа

10
0
-10

Знак `-` не является частью integer literal. Он является унарным оператором.

То есть:

- `10` — литерал;
- `-10` — унарное выражение.

### 3.2. Числа с плавающей точкой

3.14
0.5
10.0

Знак числа также является отдельным унарным оператором.

### 3.3. Boolean

true
false

### 3.4. String

"hello"
"Z language"

Строковые литералы используют правила экранирования, определённые в разделе лексики.

### 3.5. Коллекции

Массив:

[1, 2, 3]

Map:

{
    "name": "Nikita"
    "age": 25
}

Литералы структур определяются правилами конкретного `struct`.


## 4. Идентификаторы

Идентификатор является выражением, если он обозначает значение, доступное в текущей области видимости.

Пример:

x

Если:

x := 10

то выражение `x` имеет тип `int` и значение `10`.

Неизвестный идентификатор является ошибкой компиляции.

Пример:

x := unknown

Если `unknown` не объявлен, компилятор обязан сообщить ошибку разрешения имени.


## 5. Группировка

Круглые скобки используются для явного изменения порядка вычисления:

(a + b) * c

Без скобок выражение вычисляется согласно таблице приоритетов.

Скобки не создают новый тип и не изменяют тип содержащегося выражения.

Пример:

x := (10)

имеет тот же тип и значение, что и:

x := 10


## 6. Унарные операторы

Z поддерживает следующие унарные операторы:

- `-` — числовое отрицание;
- `!` — логическое отрицание;
- `+` — числовой унарный плюс.

Примеры:

-x
+x
!enabled

Оператор `-` разрешён только для числовых типов.

Оператор `+` разрешён только для числовых типов.

Оператор `!` разрешён только для `bool`.

Примеры:

x := 10
y := -x

enabled := true
disabled := !enabled

Следующее выражение является ошибкой типов:

!"hello"


## 7. Бинарные операторы

### 7.1. Арифметические

Поддерживаются:

+
-
*
/
%

Операторы `+`, `-`, `*`, `/` и `%` применяются к числовым значениям.

Для двух операндов одинакового числового типа результат имеет тот же тип.

Пример:

a := 10
b := 3

x := a + b
y := a - b
z := a * b
q := a / b
r := a % b


### 7.2. Операторы сравнения

Поддерживаются:

==
!=
<
<=
>
>=

Результатом любого оператора сравнения является `bool`.

Пример:

x := 10
y := 20

a := x == y
b := x != y
c := x < y
d := x <= y
e := x > y
f := x >= y


### 7.3. Логические операторы

Поддерживаются:

&&
||

Операнды должны иметь тип `bool`.

Результатом является `bool`.

Пример:

a := true
b := false

x := a && b
y := a || b


## 8. Короткое замыкание

Операторы `&&` и `||` вычисляются с коротким замыканием.

Для:

A && B

выражение `B` вычисляется только если `A` имеет значение `true`.

Для:

A || B

выражение `B` вычисляется только если `A` имеет значение `false`.

Пример:

x != 0 && 100 / x > 2

Если `x == 0`, правая часть не вычисляется.

Это правило является частью семантики языка и не является оптимизацией компилятора.

Порядок:

A && B

всегда означает:

1. вычислить `A`;
2. проверить результат;
3. при необходимости вычислить `B`;
4. получить итоговый `bool`.


## 9. Операторы равенства

`==` и `!=` сравнивают значения совместимых типов.

Операнды должны иметь один тип после применения разрешённых правил типизации.

Например:

10 == 10

допустимо.

Следующее выражение является ошибкой:

10 == "10"

Z не выполняет неявное преобразование `string` в `int`.

Для составных типов правила равенства определяются типом.

Структуры и коллекции не получают неявное сравнение, если такое сравнение не определено их типом.


## 10. Приоритет операторов

Операторы имеют следующий приоритет от самого высокого к самому низкому:

1. вызов функции
2. индексация
3. доступ к полю
4. унарные `+`, `-`, `!`
5. `*`, `/`, `%`
6. `+`, `-`
7. `==`, `!=`
8. `<`, `<=`, `>`, `>=`
9. `&&`
10. `||`

Таблица:

| Приоритет | Операторы | Ассоциативность |
|-----------|-----------|-----------------|
| 1 | `()` | левая |
| 2 | `[]`, `.` | левая |
| 3 | `+`, `-`, `!` | правая |
| 4 | `*`, `/`, `%` | левая |
| 5 | `+`, `-` | левая |
| 6 | `==`, `!=` | левая |
| 7 | `<`, `<=`, `>`, `>=` | левая |
| 8 | `&&` | левая |
| 9 | `||` | левая |

Пример:

a + b * c

разбирается как:

a + (b * c)

А:

a && b || c

разбирается как:

(a && b) || c

Для сложных выражений рекомендуется использовать скобки.


## 11. Ассоциативность

Бинарные арифметические и логические операторы являются левоассоциативными.

Например:

a - b - c

означает:

(a - b) - c

а не:

a - (b - c)

Аналогично:

a / b / c

означает:

(a / b) / c


## 12. Приоритет и типы

Приоритет определяет структуру выражения до проверки типов.

Например:

1 + 2 * 3

разбирается как:

1 + (2 * 3)

Результат:

7

Тип выражения:

int


## 13. Вызов функции

Функция вызывается с помощью круглых скобок:

add(10, 20)

Аргументы разделяются запятыми.

Общий вид:

function(argument1, argument2, ...)

Количество аргументов должно соответствовать объявлению функции.

Тип каждого аргумента должен соответствовать типу соответствующего параметра.

Пример:

fn add(a: int, b: int): int {
    return a + b
}

x := add(10, 20)

`x` имеет тип `int`.


## 14. Вызов значения функционального типа

Если выражение имеет функциональный тип, оно также может быть вызвано:

fn add(a: int, b: int): int {
    return a + b
}

f := add
x := f(10, 20)

Вызов применяется к результату выражения:

f(10, 20)

а не только к идентификаторам.

Поэтому допустимы вложенные вызовы:

get_factory()(10)


## 15. Порядок вычисления аргументов

Аргументы функции вычисляются слева направо.

Для:

foo(A, B, C)

порядок всегда:

1. вычислить `A`;
2. вычислить `B`;
3. вычислить `C`;
4. выполнить вызов `foo`.

Компилятор не имеет права менять этот порядок.

Это правило необходимо для детерминированного поведения программ.


## 16. Индексация

Индексирование используется для получения элемента коллекции:

values[0]

Индекс должен иметь допустимый для данного типа индексный тип.

Для массива и среза индексом является `int`.

Пример:

numbers := [10, 20, 30]

x := numbers[0]

Результат:

10


## 17. Индексация массива

Для массива:

[N]T

допустимый индекс находится в диапазоне:

0 <= index < N

Например:

numbers := [3]int{1, 2, 3}

numbers[0]
numbers[1]
numbers[2]

являются допустимыми.

`numbers[3]` является ошибкой выхода за границы.


## 18. Индексация динамического массива

Для:

[]T

индекс также начинается с `0`.

Если индекс находится вне диапазона текущего количества элементов, выполнение завершается runtime error.

Компилятор обязан диагностировать выход за границы, если он может доказать его во время компиляции.

Например:

numbers := [1, 2, 3]

x := numbers[10]

должно быть отклонено компилятором, если значение индекса известно статически.


## 19. Индексация map

Map индексируется значением ключа:

ages["Ann"]

Если ключ существует, выражение возвращает значение соответствующего типа.

Если ключ отсутствует, это runtime error.

Z не использует неявное значение `0`, `false`, `""` или другое zero value для отсутствующего ключа.

Это позволяет отличать:

"ключ отсутствует"

от:

"ключ существует и его значение равно zero value".

В будущем стандартная библиотека может предоставить безопасную операцию проверки существования ключа.


## 20. Доступ к полям

Для доступа к полю структуры используется оператор `.`:

user.name

Если:

struct User {
    name: string
    age: int
}

то:

user.name

имеет тип `string`, а:

user.age

имеет тип `int`.

Поле должно существовать в статическом типе значения.

Динамического поиска поля во время выполнения нет.


## 21. Цепочки доступа

Доступ к полям можно объединять:

user.address.city

Это эквивалентно:

(user.address).city

Аналогично можно комбинировать поля и индексацию:

users[0].name

map_users["admin"].name

items[0].metadata["id"]


## 22. Приоритет postfix-операций

Вызов, индексация и доступ к полям имеют очень высокий приоритет.

Например:

users[0].profile.name

разбирается как:

(((users[0]).profile).name)

А:

get_user().name

разбирается как:

(get_user()).name


## 23. Вложенные выражения

Любое выражение может быть частью другого выражения, если его тип соответствует требуемому типу.

Пример:

result := add(a * 2, b + 10)

Разбор:

1. `a * 2`
2. `b + 10`
3. `add(...)`
4. присваивание результата переменной `result`.


## 24. Приоритет вызова и индексации

Выражение:

foo()[0].name

разбирается как:

((foo())[0]).name

Сначала выполняется `foo()`.

Затем результат индексируется.

Затем у результата читается поле `name`.


## 25. Выражения и присваивание

Присваивание:

x = expression

не является обычным бинарным оператором.

Правая часть вычисляется полностью до изменения значения `x`.

Пример:

x = x + 1

порядок:

1. прочитать текущее значение `x`;
2. вычислить `x + 1`;
3. проверить совместимость типов;
4. записать результат в `x`.


## 26. Запрет неявных преобразований

Z не выполняет неявные преобразования типов в выражениях.

Например:

x: int = 10

y: float = x

является ошибкой.

Необходимо явное преобразование, если соответствующая операция поддерживается стандартом:

y: float = float(x)

Аналогично:

x + 1.5

является ошибкой, если `x` имеет тип `int`.

Компилятор не должен самостоятельно выбирать тип преобразования.


## 27. Числовые операции

Для числовых операндов типы должны быть совместимыми.

Z не выполняет автоматическое продвижение:

int -> float

или:

float -> int

Например:

x: int = 10
y: float = 2.5

Следующее выражение недопустимо:

x + y

Необходимо явно привести один из операндов.


## 28. Деление

Оператор `/` выполняет деление согласно типу операндов.

Для `int` результат имеет тип `int`.

Для `float` результат имеет тип `float`.

Например:

10 / 3

даёт целочисленный результат.

10.0 / 3.0

даёт результат типа `float`.

Деление целого числа на ноль является runtime error.

Деление `float` регулируется правилами выбранного числового представления Z.


## 29. Остаток от деления

Оператор `%` применяется к целым числам.

Пример:

10 % 3

результат:

1

Применение `%` к `float` является ошибкой типов.

Остаток от деления на ноль является runtime error.


## 30. Переполнение

Переполнение целочисленного типа не должно быть неявно неопределённым поведением.

Компилятор и runtime обязаны следовать единому правилу, определённому реализацией Z.

Рекомендуемое правило базовой реализации Z:

- переполнение проверяется;
- переполнение вызывает runtime error;
- арифметика не переходит молча в wraparound.

Это правило делает поведение программы более предсказуемым для человека и ИИ.


## 31. Порядок вычисления бинарных выражений

Для обычного бинарного оператора:

A op B

сначала вычисляется `A`, затем `B`.

Исключение:

&&
||

Для них действует короткое замыкание.

Следовательно:

foo() + bar()

всегда вызывает:

1. `foo()`;
2. `bar()`;
3. операцию `+`.


## 32. Побочные эффекты

Выражение может содержать вызов функции с побочным эффектом:

log("hello")

В таком случае порядок вычисления, определённый этой спецификацией, является обязательным.

Компилятор не может переупорядочивать такие вычисления только потому, что математический результат кажется эквивалентным.

Оптимизация разрешена только тогда, когда она сохраняет наблюдаемую семантику программы.


## 33. Отсутствие неявной оценки

Z не выполняет выражения заранее только потому, что они выглядят константными.

Например:

foo() + bar()

не может быть заменено перестановкой:

bar() + foo()

если это может изменить наблюдаемое поведение программы.


## 34. Константные выражения

Выражение, состоящее только из значений, известных компилятору, может быть вычислено во время компиляции.

Например:

10 * 20 + 5

может быть вычислено как:

205

Результат такой оптимизации должен быть идентичен результату обычного выполнения.

Вызов функции с потенциальным побочным эффектом не является константным выражением.


## 35. Тип результата

Каждое корректное выражение имеет ровно один статический тип.

Примеры:

10              -> int
3.14            -> float
true            -> bool
"hello"         -> string
a + b           -> тип операндов
a == b          -> bool
foo()           -> тип результата foo
numbers[0]      -> тип элемента
user.name       -> тип поля name

Тип выражения определяется во время компиляции.


## 36. Типизация условных выражений

Z не использует автоматическое приведение произвольных значений к `bool`.

Следующее недопустимо:

if 1 {
}

Условие должно иметь тип:

bool

Правильно:

if x > 0 {
}


## 37. Отсутствие truthy/falsy

В Z нет неявного правила:

0 == false
"" == false
[] == false

Значения `int`, `string`, `array` и другие типы не могут использоваться как `bool`.

Например:

if name {
}

является ошибкой, если `name` имеет тип `string`.

Необходимо явно сформировать boolean expression:

if name != "" {
}


## 38. Ошибки выражений

Ошибки выражений делятся на два класса.

### Compile-time errors

К ним относятся:

- неизвестный идентификатор;
- неизвестный оператор для типа;
- несовместимые типы;
- неправильное количество аргументов;
- неправильные типы аргументов;
- неизвестное поле;
- недопустимый индексный тип;
- недопустимое выражение в конкретном контексте.

### Runtime errors

К ним относятся:

- деление integer на ноль;
- деление на ноль;
- выход за границы коллекции;
- отсутствие ключа map;
- другие ошибки, которые невозможно гарантированно определить во время компиляции.

Каждая ошибка должна иметь стабильный error code согласно разделу ошибок Z.


## 39. Приоритет AST над текстовым представлением

После разбора выражения компилятор должен получить однозначное AST.

Например:

a + b * c

должно создавать структуру, эквивалентную:

Binary(
    left = Identifier("a"),
    operator = "+",
    right = Binary(
        left = Identifier("b"),
        operator = "*",
        right = Identifier("c")
    )
)

А не:

Binary(
    left = Binary(
        left = Identifier("a"),
        operator = "+",
        right = Identifier("b")
    ),
    operator = "*",
    right = Identifier("c")
)


## 40. Рекомендуемая форма AST

Для выражений рекомендуется использовать следующие узлы:

LiteralExpr
IdentifierExpr
UnaryExpr
BinaryExpr
CallExpr
IndexExpr
FieldExpr
ArrayExpr
MapExpr
StructExpr

Каждый узел должен содержать:

- тип узла;
- source span;
- дочерние узлы;
- необходимые семантические данные после type checking.


## 41. Source span

Каждое выражение AST должно сохранять диапазон исходного кода:

start line
start column
end line
end column

Это необходимо для:

- диагностики;
- IDE;
- LSP;
- AI tooling;
- автоматического исправления кода;
- точного отображения ошибок.


## 42. Детерминированность

Для одного и того же исходного текста и одной и той же версии Z:

- lexer должен создавать одинаковый поток токенов;
- parser должен создавать одинаковый AST;
- type checker должен получать одинаковые типы;
- выражения должны иметь одинаковую семантику;
- порядок вычисления должен быть одинаковым.

Реализация не должна менять смысл программы в зависимости от платформы, если это не оговорено спецификацией.


## 43. Полный пример

struct User {
    name: string
    age: int
}

fn calculate(age: int, limit: int): bool {
    return age >= limit && age < 100
}

user := User{
    name: "Nikita"
    age: 25
}

limit := 18

valid := calculate(user.age, limit)

if valid {
    print(user.name)
}

Порядок вычисления выражения:

calculate(user.age, limit)

1. вычислить `user`;
2. получить поле `age`;
3. вычислить `limit`;
4. выполнить `calculate`;
5. получить `bool`;
6. присвоить результат переменной `valid`.


## 44. Пример сложного выражения

result := users[0].scores["math"] + calculate(users[0].age, 18) * 2

Приоритет означает:

result := users[0].scores["math"] +
         (calculate(users[0].age, 18) * 2)

Внутри вызова:

calculate(users[0].age, 18)

сначала вычисляется:

users[0]

затем:

.users[0].age

затем второй аргумент:

18

затем выполняется вызов функции.

После этого выполняется умножение на `2`.

Затем выполняется сложение.


## 45. Правило однозначности

Любое выражение Z должно иметь единственную интерпретацию согласно грамматике, таблице приоритетов и правилам типов.

Если выражение трудно читать человеку, рекомендуется использовать скобки.

Например:

a && b || c

формально однозначно, но:

(a && b) || c

предпочтительнее в коде, если логическая структура выражения важна.


## 46. Философия выражений Z

Система выражений Z следует четырём принципам:

1. Явность.
2. Предсказуемость.
3. Статическая проверяемость.
4. Простота анализа машиной.

Z не пытается угадывать намерение программиста.

Если операция требует преобразования типа, преобразование должно быть выражено явно.

Если выражение может иметь побочный эффект, его порядок вычисления должен быть определён спецификацией.

Если выражение некорректно, компилятор должен сообщить структурированную и стабильную ошибку.


## 47. Краткая справка

Унарные:

+expr
-expr
!expr

Арифметика:

expr + expr
expr - expr
expr * expr
expr / expr
expr % expr

Сравнение:

expr == expr
expr != expr
expr < expr
expr <= expr
expr > expr
expr >= expr

Логика:

expr && expr
expr || expr

Вызов:

fn(expr1, expr2)

Индексация:

value[index]

Поле:

value.field

Группировка:

(expr)

Основное правило Z:

выражение должно быть однозначным, статически проверяемым и иметь один определённый результат и тип.


## 48. Примечание о расширениях

Следующие возможности намеренно не входят в базовую версию выражений Z:

- ternary operator;
- null-coalescing operator;
- optional chaining;
- operator overloading;
- implicit conversions;
- user-defined operators;
- postfix increment/decrement;
- exponentiation operator;
- pattern matching expressions;
- lambda syntax.

Они могут быть рассмотрены в будущих версиях только при наличии доказанной необходимости.

Базовый язык должен оставаться минимальным и детерминированным.
