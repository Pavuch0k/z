# Схема транслятора языка Z

Транслятор Z выполняет последовательную обработку исходного текста. Каждый следующий блок получает результат предыдущего и либо передаёт промежуточное представление дальше, либо завершает трансляцию с ошибкой.

## 1. Общая схема

```text
Исходный текст (.z)
        │
        ▼
┌───────────────────┐
│ Лексический       │  текст → последовательность лексем
│ анализатор        │
└─────────┬─────────┘
          │ лексемы
          ▼
┌───────────────────┐
│ Синтаксический    │  лексемы → дерево разбора / AST
│ анализатор        │
└─────────┬─────────┘
          │ AST
          ▼
┌───────────────────┐
│ Семантический     │  проверка типов, областей видимости,
│ анализатор        │  правил использования конструкций
└─────────┬─────────┘
          │ проверенное AST + таблицы символов
          ▼
┌───────────────────┐
│ Генеративный      │  генерация целевого кода / байткода
│ блок              │
└─────────┬─────────┘
          │
          ▼
   Исполняемая форма
```

## 2. Взаимодействие блоков

### 2.1. Лексический анализатор

Вход: исходный текст программы в UTF-8.

Выход: поток лексем (идентификаторы, ключевые слова, литералы, операторы, разделители) с позициями в тексте.

Действия:

- удаляет пробелы и комментарии `//`;
- распознаёт наиболее длинную допустимую лексему;
- сообщает лексические ошибки (недопустимый символ, незакрытая строка).

При ошибке трансляция останавливается. Синтаксический анализатор лексемы с ошибкой не получает.

### 2.2. Синтаксический анализатор

Вход: поток лексем.

Выход: абстрактное синтаксическое дерево (AST) по правилам РБНФ.

Действия:

- проверяет соответствие программы грамматике;
- строит узлы объявлений, операторов и выражений;
- различает целочисленные, вещественные, строковые и логические выражения согласно РБНФ.

Строковый литерал не может оказаться под унарным минусом или в мультипликативной конструкции: такие формы грамматикой не порождаются.

При синтаксической ошибке строится сообщение с позицией и трансляция завершается.

### 2.3. Семантический анализатор

Вход: AST.

Выход: то же AST, дополненное типами и связями с таблицей символов, либо ошибка.

Действия:

- строит области видимости и таблицу символов;
- проверяет объявление имени до использования;
- сопоставляет типы в объявлениях, присваиваниях, вызовах и `return`;
- проверяет, что идентификаторы в целочисленных, вещественных, строковых и логических выражениях имеют соответствующий тип;
- проверяет условия `if` / `loop` на тип `flag`;
- проверяет границы и типы цикла `for`;
- проверяет правила `in` / `out`.

Семантический блок не исправляет программу автоматически и не выполняет неявных преобразований типов.

### 2.4. Генеративный блок

Вход: семантически корректное AST и таблицы символов.

Выход: целевое представление программы (код реализации транслятора).

Действия:

- обходит проверенное AST;
- генерирует код для выражений, операторов, функций и ввода-вывода;
- сохраняет порядок вычисления, заданный семантикой языка.

Генерация выполняется только после успешного прохождения лексического, синтаксического и семантического анализа.

## 3. Поток ошибок

```text
Лексическая ошибка ──► сообщение ──► останов
Синтаксическая ошибка ──► сообщение ──► останов
Семантическая ошибка ──► сообщение ──► останов
Успех всех блоков ──► генерация кода
```

Ошибки времени выполнения (деление на ноль, выход за границы массива, неверный ввод) обнаруживаются при исполнении сгенерированной программы и к этапам трансляции не относятся.

## 4. Краткая характеристика этапов

| Блок | Вход | Выход | Главная задача |
| ---- | ---- | ----- | -------------- |
| Лексический | текст | лексемы | выделить слова языка |
| Синтаксический | лексемы | AST | проверить структуру по РБНФ |
| Семантический | AST | типизированное AST | проверить смысл и типы |
| Генеративный | типизированное AST | целевой код | получить исполняемую форму |
